How should "threads made of clustered tickets" actually work?

Same idea, three different mechanics. Pick the one that feels closest to what you pictured.

A

Free spatial canvas (implicit clustering)

Tickets are sticky notes on an infinite corkboard. You place them anywhere. Threads are computed from how close tickets are to each other — drag one near a group and it silently joins that thread. Zoomed out, tight clusters collapse into one label bubble.

B

Explicit thread frames (you choose membership)

Each thread is a named container box you can move around the canvas like a sub-board. Tickets belong to a frame because you dropped them into it, not because of position. Zoomed out, the frame itself shrinks to a labeled card.

C

Category lanes + explicit threads inside (hybrid)

Board is split into fixed category lanes (Work, Personal, Learning…). Inside each lane, threads are still explicit named groups (like B), so clustering is only ever within one category — simpler to reason about and query.

A — Free canvas feels magical, but

  • Clustering must be inferred (fuzzy: what counts as "close enough"?)
  • Harder to guarantee a ticket has exactly one thread
  • Needs a real clustering/layout algorithm to build and tune

B / C — Explicit membership

  • A ticket's thread is a simple foreign key — easy, reliable, fast to build
  • You still drag tickets freely; the "thread" is just what frame they're in
  • C adds fixed category lanes on top of B for extra structure
